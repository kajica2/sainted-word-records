# Plan — Hip-Hop Freestyle Studio "Spit Live" (`/spit`)

## Goal

Ship the **Spit Live** page — a focused one-take freestyle studio for hip-hop
MCs. Drop a beat, switch on the mic, hit record, done. Visuals react to both
beat AND voice. Built on top of the MediaInput foundation (PR #101).

This is **PR 2 of 4** in the user's chosen sequence
(live-camera-mic → spit-live → tiktok → camera-enhance).

## Scope

### In
- `/spit` page (HTML + CSS + inline controller)
- Beat loading: file picker, drag-drop, YouTube-link paste (deferred — see below)
- Beat playback: play/pause/seek + waveform display
- BPM + key detection via `audio-analysis-v2.js` (already exists at repo root)
- Mic + camera integration via the MediaInput foundation (PR #101)
- Reactive canvas — beat-driven visuals + voice-driven reactivity
- FX trigger tray: Punch / Flow / Ride / Stutter / Echo / Black (one-shot visual moments)

### Architecture — runtime

`client/swr-spit-runtime.client.js` (IIFE + global pattern, matching foundation modules):

- `window.SWR_SPIT.create(beatEl, micEl, stageEl, options)` — factory
- Instance state machine: `LOADING → READY → RECORDING → SAVED → READY`
- Public methods: `loadBeat(file)`, `playBeat()`, `pauseBeat()`, `seekBeat(s)`, `toggleMic()`, `triggerFx(name)`, `startRecording()`, `stopRecording()`, `getState()`
- Pulls BPM + key from `audio-analysis-v2.js` (already loaded as a global `SWR_AUDIO_ANALYSIS`)
- Reactive canvas uses an existing engine variant as the base renderer — **recommend `neon`** as it's the simplest beat-reactive path with `window.SWR_AUTOMIX` already wired

### Architecture — FX library

`client/swr-spit-fx.client.js` (IIFE + global pattern):

- `window.SWR_SPIT_FX.trigger(name, ctx)` — applies a named FX
- 6 FX: `punch` (white flash + 200ms scale), `flow` (sustained blur ramp), `ride` (chromatic split), `stutter` (3x frame repeat), `echo` (rgba trail), `black` (full fade to black for 1s)
- Pure functions over a 2D canvas context — no DOM dependency
- Each FX is a state machine: `PENDING → ACTIVE → DECAY → DONE` (auto-cleanup)

### Architecture — recording

- Use `mediaInput.startRecording(canvas, options)` from PR #101
- `canvas` = the stage canvas
- `audio` comes from mediaInput (mic stream already attached)
- `options.beatDestination` = the beat `<audio>` element's `captureStream()` for synced audio
- Output: `.webm` mime (already handled by MediaInput's codec selection)

## Persistence keys

- `swr.spit.lastBeatName` — string (last loaded beat filename)
- `swr.spit.lastInterval` — string (last recording duration, for analytics)

## Browser requirements

- Same as PR #101: HTTPS or localhost for `getUserMedia`
- `audio-analysis-v2.js` uses Web Audio decodeAudioData — requires AudioContext

## Out of scope (intentional)

- Multi-MC cypher mode
- Auto-transcribe (Web Speech API is unreliable + non-deterministic)
- Vocal enhancer DSP (would need a compressor/eq library)
- YouTube link support (CORS + ToS issues; defer to follow-up)
- Sharing / posting integration (out of scope for engine; later PRs add publish flows)
- Save Session (project files; needs a project data model)
- Punch/Flow/Ride FX presets beyond the 6 spec'd

## Known risks

- **Audio analysis dependency** — `audio-analysis-v2.js` decodes the whole beat offline for BPM. Long files (>10min) could block. Mitigation: add a chunked decode fallback or cap to first 60s. Defer to follow-up if it becomes a problem.
- **Canvas + media recording sync** — combining `canvas.captureStream()` + mic + beat audio into one MediaRecorder stream. Existing MediaInput handles this; we just need to pass the right streams.
- **iOS Safari** — needs `playsinline` on the canvas-stripped video. Spit Live has no `<video>` element (canvas only), so this risk is moot.
- **Pre-existing cover-behaviour flake** at `scripts/check-automix-smoke.mjs:1010-1038` — still present, will likely fail again on this PR. Merge with `--admin` + PR comment per established pattern.
