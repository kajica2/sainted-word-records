## TL;DR — top 5 things to fix

1. **Only `engine.html` is installable today.** `pwa-bootstrap.js` is loaded in exactly 1 of 69 HTMLs in this repo. The other 68 never register the service worker, never show the install prompt, never get the update toast, and never get offline messaging. Widen the wiring.

2. **Manifest scope is `"/engine/"`.** That single decision is why nothing else is installable. A user visiting `/enhance` and accepting the install prompt lands on `/engine/`. The manifest needs a real landing page — either `/` (the landing) or `/engine` but the scope should be `/` so all pages qualify.

3. **Install-card dismissal is in-memory only.** No `localStorage`. A user who dismisses the install card on one page gets re-prompted on every page they visit. Add a `localStorage` flag (one-shot per origin, with a "show again" debug knob).

4. **`icon-maskable-512.png` is byte-identical to `icon-512.png`.** A maskable icon must have a "safe zone" (the inner 80% circle) — the outer 20% is allowed to be cropped by launchers. The current icon doesn't have one, so adaptive icon launchers (Android 8+) crop user-visible content. Re-export a real maskable version.

5. **`pwa-bootstrap.js` is a non-module script** that depends on the Vite `strip-absolute-module-scripts` plugin to convert `type="module"` → `defer`. New pages (the variants + the new enhance/photo/video_single pages) are at risk of getting it wrong. Either commit to the plugin as the official pattern, or make pwa-bootstrap work as a real module.

## Cache-size impact

Full-html precache budget if every page goes into `APP_SHELL`:
- 35 top-level HTMLs: ~1.5 MB total (swr-app.html alone is 387 KB)
- 23 variants: ~1.5 MB total (music_video.html is 183 KB)
- 11 persona variants: ~300 KB total
- **Total: ~3 MB** precache — well within the 60 MB origin quota

This is a soft "fine, but a lot" number. Most users will only install once and only ever visit a small subset. The SW doesn't need to precache every page — it can runtime-cache them on first fetch (which it already does). The fix is: don't bother precaching them all. Just register pwa-bootstrap on every page so the SW + manifest are available; runtime cache the HTMLs as the user navigates.

**Recommended `APP_SHELL` after fixes:** `/` (landing), `/engine/`, `/enhance/`, `/video_single/`, `/offline.html`, plus the icons + manifest. ~5 entries. All other HTMLs runtime-cache on first fetch.
