# Shared harness orchestration

This reference is the single execution owner for omb-harness mode routing and
omb-orch-harness intent routing. Read it after selecting a mode, then execute here;
do not invoke one wrapper from the other. Only the main session spawns agents.
Subagents cannot spawn subagents. All agents return `<omb>DONE|RETRY|BLOCKED</omb>`
plus the complete `.claude/rules/common/output-contract.md` result envelope.

## Mode matrix

| Mode | Agent sequence | Write permission and terminal gate |
|---|---|---|
| `inventory` | @harness-explorer | read-only; report inventory and cross-references |
| `hook-audit` | @harness-explorer | read-only; report hook/matcher/exit-code findings |
| `skill-audit` | @harness-explorer | read-only; report skill assignments and missing references |
| `plan` | @harness-explorer → @harness-design | read-only; Stop before implementation and return design |
| `verify` | @harness-verify | read-only; PASS or report failures; never auto-fix |
| `prompt` | @harness-prompt-engineer | scoped harness Markdown only; evaluate/fix/reevaluate, max 3 rounds |
| `default` | @harness-explorer → @harness-design → @harness-implement → @harness-verify | implement approved scope; independent verification PASS |
| `fix` | @harness-explorer → @harness-design → @harness-implement → @harness-verify | diagnosis-first minimal repair; independent verification PASS |
| `new-feature` | @harness-explorer → @harness-design → @core-critique → @harness-implement → @harness-verify | critique APPROVE before write; independent verification PASS |

`plan` also handles improvement suggestions: return recommendations and do not
implement them. A later implementation request chooses a writing mode. For a
new component type with no existing state, default discovery may be skipped with
an explicit reason; never skip diagnosis for fix or evidence needed for design.

## Scope and permissions

Write only authorized `.claude/`, `CLAUDE.md`, `CLAUDE.local.md`, or `.mcp.json`
files. No application code is modified. Preserve user-added hook matchers and
permission entries; keep shell injections portable and never weaken permissions
(no `bypassPermissions`, no bare write/exec allow tokens). Read-only agents
@harness-explorer, @harness-design, @core-critique, and @harness-verify must return
empty changed_files. Prompt mode is limited to `.claude/agents/**/*.md` and
`.claude/skills/**/SKILL.md` under the existing prompt-engineer scope.

Validate field names and conventions against
`.claude/rules/harness/claude-code-harness.md`; do not invent frontmatter fields.
Generated compatibility mirrors are regenerated by the host's exporter, never
hand-edited by harness agents. The caller retains authority for any export step.

## Shared sequence

1. **Explore:** give @harness-explorer the task, allowed targets and knowledge_context.
   Inventory scopes/settings/CLAUDE/agents/skills/rules/hooks/MCP/memory as relevant.
   In fix mode, isolate symptoms and configuration causes; in hook-audit, inspect
   hook entries, scripts, exit codes, matcher syntax and path references; in
   skill-audit, inspect preload assignments, orphaned skills, missing targets and
   invocation patterns. Read-only audit modes finish with this report.
2. **Design:** give @harness-design the original task and verified explorer findings.
   Require exact paths, valid frontmatter, prompt structure, cross-references, and
   existing convention compatibility. Fix mode proposes the smallest repair;
   plan mode returns recommendations/specification now and stops before any writer.
3. **Critique (new-feature):** give @core-critique the design and original evidence.
   Check correctness, scope, field validity, output contract, security and references.
   Require APPROVE; REJECT returns to design with feedback, max 2 design retries.
4. **Implement (writing modes only):** give @harness-implement the design, allowed
   paths, original evidence, and critique concerns if applicable. Change only the
   approved design, preserve other work and return exact changed_files. Do not
   transform plan/verify/audit modes into a write merely because improvements exist.
5. **Verify:** independent @harness-verify reads changed files and original task.
   Check frontmatter, hook exits, permission syntax, cross-references, output
   contract, conventions, settings.json, MCP, CLAUDE and security. Fix mode also
   checks the original symptom and regressions. PASS finishes; FAIL sends findings
   to @code-debug, then retries implementation, max 3 retries. No writer self-review
   substitutes for this gate. BLOCKED stops the affected workflow.

Standalone verify applies step 5 without a writer. Standalone prompt delegates the
scoped evaluate-diagnose-fix-reevaluate cycle to @harness-prompt-engineer using the
omb-prompt-review methodology and reports score delta, checks and changed files.
Every handoff includes original task, evidence, design/critique context when relevant,
and changed files for verification. Independent reviewers do not receive each
other's opinions.

## Watchdog and retries

Every spawn, including @code-debug and retries, follows the single-agent watchdog
in `.claude/rules/workflow/11-subagent-watchdog.md`; thresholds live there only.
When `OMB_SUBAGENT_WATCHDOG=false`, spawn synchronously. Otherwise:

1. Spawn with `run_in_background: true`, record agentId, spawn_wall_clock and
   last_progress_at. Poll TaskOutput with OMB_SUBAGENT_POLL_SLICE_S slices.
2. Reset inactivity only on output progress. On completed output, parse and enforce
   the terminal envelope in the main session; background Stop hooks do not fire.
3. On inactivity or hard ceiling breach, TaskStop, then retry once within both
   per-agent and aggregate OMB_SUBAGENT_RETRY_MAX; aggregate allowance dominates.
4. Writing @harness-implement or @harness-prompt-engineer retries require a clean
   boundary: worktree isolation under workflow/07-worktree-protocol.md or explicit
   clean/rollback before respawn. Preserve unrelated user changes; absence of that
   boundary blocks retry. Read-only agents can retry without rollback.
5. Implement and verify are critical in writing workflows: exhausted loss returns
   BLOCKED. A lost standalone review/validation agent surfaces non-success. Other
   optional exploration can degrade with a recorded gap, but never manufacture an
   APPROVE or PASS needed by the selected mode.

Design retries max 2; implementation retries max 3 with @code-debug between;
prompt internal rounds max 3. These semantic retries do not expand the watchdog's
aggregate retry allowance. After exhaustion, return the exact blocker and required
next action; request user guidance only when it is actually needed for progress.

## Context Passing

Read `.claude/skills/omb-context/references/workflow-handoff.md` and relay
knowledge_context unchanged: bundle_path, bundle_id, query_signature,
source_fingerprint, evidence_ids, adopted, rejected_with_reason,
unresolved_questions. Preserve root/layer/revision and complete conditions.
Request host rebuild for stale evidence; do not duplicate ranking or budget policy.

## Completion

Require the selected mode's actual terminal evidence. Return summary, artifacts,
changed_files, concerns, blockers, retryable and next_step_hint. Read-only modes
have no changed files. Failed verification returns RETRY with bounded repair or
BLOCKED when authority/capability/retry budget is exhausted; never claim DONE from
an expected result. Mode selection and write scope remain unchanged through retries.
