# SWR Orchestrator

A small, read-only-but-appending orchestrator that watches SWR work
and writes a daily journal to an Obsidian vault.

## What it does

1. **Daily journal** at `<vault>/Journal/YYYY-MM-DD.md` with frontmatter
   (`day`, `tags`, `branch`, `head`, `session_id`). Each append is
   sectioned (`## Commit <hash>`, `## Event · <type>`, `## Session end`).
2. **Auto-logs every commit** via the post-commit hook
   (`.git/hooks/post-commit` → `tools/swr-post-commit-hook.sh` →
   `node tools/swr-journal-log.mjs commit <sha>`).
3. **Manual log of any event** with `--summary` and arbitrary
   `--key "value"` flags: `event <type>`.
4. **Session-end rollup** that captures recent commits, files
   changed, top-20 open TODOs, and the active P0/P1 highlights from
   `docs/PLANS/`.
5. **Map of contents** at `<vault>/MOCs/SWR.md` with Dataview blocks
   the Obsidian user can render to navigate the journal + plans.

## Setup

```bash
node tools/swr-vault-init.mjs
# creates the vault at $SWR_VAULT (default
# /Users/kaidejuricmassbook/Documents/SWR-Vault) or falls back to
# .obsidian-swr/ inside the repo if that path is unwritable
```

Open the vault in Obsidian:

```
File → Open vault → <vault path printed by the script>
```

Install the post-commit hook (one-time):

```bash
cp tools/swr-post-commit-hook.sh .git/hooks/post-commit
chmod +x .git/hooks/post-commit
```

(The hook silently no-ops if the logger or the vault is missing —
so `git commit` is never blocked by an optional tool.)

## Subcommands

### `node tools/swr-journal-log.mjs init`

Bootstrap today's journal + the MOC. Idempotent.

### `node tools/swr-journal-log.mjs commit <sha> [path]`

Log a single commit. Called by the post-commit hook with the new HEAD
sha; pass an explicit path to log just one of the changed files.

### `node tools/swr-journal-log.mjs event <type> --key "value" ...`

Log a structured event. Example:

```bash
node tools/swr-journal-log.mjs event audit \
  --summary "Architect audit found 4 P1, 11 P2, 6 P3" \
  --agent "swr-check" \
  --url "docs/PLANS/architecture-audit-2026-10.md"
```

`--summary` is required. Arbitrary `--key "value"` pairs become
`- **key:** value` lines in the section.

### `node tools/swr-journal-log.mjs session [summary-file]`

Log a session-end block. If `summary-file` is given, its contents are
embedded under `### Summary`. Otherwise, the SWR_SESSION_SUMMARY env
var is used (so a shell pipeline can inject the summary).

### `node tools/swr-journal-log.mjs readme`

Re-emit the MOC if it was deleted or you want a fresh Dataview query.

## Per-session kick

Capture a session, then log it:

```bash
SWR_SESSION_SUMMARY="$(node tools/swr-session-summary.mjs HEAD~3)" \
  node tools/swr-journal-log.mjs session
```

`swr-session-summary.mjs` is read-only: it shells out to `git log`,
`git diff`, and a `grep` for TODO/FIXME. It does **not** modify any file
and does **not** run `npm test` (that's the post-commit hook's job,
and the test gate runs on every push anyway).

## Path

The orchestrator reads `SWR_VAULT` first, then falls back to
`./.obsidian-swr/` inside the repo, then to
`/Users/kaidejuricmassbook/Documents/SWR-Vault`. Override with:

```bash
export SWR_VAULT=/path/to/your/vault
node tools/swr-vault-init.mjs
```

## Map of contents

`<vault>/MOCs/SWR.md` ships a Dataview MOC:

- Journal (last 30 days) — dataview table by `day`
- Active P0/P1 backlog — dataview list of plans tagged `live`

Open Obsidian's MOC view (Dataview plugin required) to navigate.

## SWR team integration

The SWR team skills (Ops, Twin, Check) can call the orchestrator
from their subagent context:

```
> "SWR-Ops, before you decompose the next batch, run
>  node tools/swr-journal-log.mjs event batch --summary '...' to
>  log what was just decided."
```

```
> "SWR-Check, after you finish verifying, run
>  node tools/swr-journal-log.mjs event verify --summary '...' to
>  log your verdict."
```

The orchestrator itself never reads or writes SWR code. It writes
only the journal.

## What it does NOT do

- ❌ Modify SWR code (it never touches the repo's source).
- ❌ Run tests (that's `npm run check` and the post-commit hook's
  job, which is `node tools/swr-journal-log.mjs commit`, not test
  running).
- ❌ Sync to git remotes.
- ❌ Send notifications or write to other services.

## Files in this orchestrator

- `tools/swr-vault-init.mjs` — initialize the vault (one-time)
- `tools/swr-journal-log.mjs` — the writer (init / commit / event / session / readme)
- `tools/swr-session-summary.mjs` — read-only summary generator
- `.git/hooks/post-commit` — auto-log every commit
- `tools/SWR-ORCHESTRATOR.md` — this file
