# Kai character sigil

A procedural character sigil — generated by
`tools/generate-sigil-kai.mjs` from the seed `KAI`. Lives at
`press/sigil-kai.svg`. Use it wherever the project needs a
character mark that *is* the work, not a logo for the work.

## What the sigil says

The sigil is a single stroke-coloured SVG drawn in a 1000×1000
viewBox. Read it from the inside out — each layer maps to a
domain Kai works across:

1. **Central node — a 9-pointed star.** 9 is *almost-complete*: one
   point short of the 10-fold rosette. The center is whole but not
   closed. That's the AI reflection's phrase: *an abundance
   problem*, not a closed book. 9 also fits a 3×3 grid — the
   universal composable block (9 audio bands, 9 reactors, 9
   archetypal reactions in the engine's reactor system).

2. **Hexagonal inner ring — 6 cardinal nodes.** The hexagon is the
   simplest shape that tiles the plane and is the geometry of a
   benzene ring — chemistry, the first cross-domain language. 6
   corresponds to the engine's six *primary* audio features
   (bass, mid, treble, air, sub, rms) before any derived ones
   (beat, onset, centroid). The ring is stroked, not filled —
   connection, not enclosure.

3. **Heptagonal middle ring — 7 nodes around an irregular
   heptagon.** 7 is the number of major disciplines Kai works
   across (music, image, code, AI, design, business, experiment),
   per the AI reflection document. The first node is enlarged
   (music, the first instrument); the other six are smaller. The
   heptagon is deliberately irregular — disciplines don't sit on
   a regular grid.

4. **Dodecagonal outer ring — 12 nodes sized as a small FFT.** 12
   is the chromatic scale (the engine's tonal signature) and the
   12-fold rosette — the most "complete" form the engine can
   produce without overlap. The 12 are sized by the audio band
   each represents (sub, bass, mid, treble, air × 2 positions),
   so the ring is itself the engine's audio analysis in
   geometric form. The sigil *contains* the engine.

5. **Corner triangles — 4 small outward-pointing marks at the
   corners of an enclosing square.** The square is the device
   frame, the page, the screen — the place where the sigil
   lives. The corners are where the sigil *exits* its frame,
   where the inside becomes the outside. Each corner has a small
   triangle pointing outward, like the four corners of a stage.

6. **Enclosing circle — the universe boundary.** A single thin
   circle that ties the whole composition together. The circle is
   the unbroken loop, the audio waveform, the universe. The sigil
   sits inside it but is not bounded by it — there is always one
   ring's worth of negative space between the inner work and the
   outer edge.

## Aesthetic notes

All elements are **stroked, not filled** — sigil aesthetic, not
logo aesthetic. The ink is `currentColor`, so the embedding
page sets the colour via CSS — light on dark, gold on black,
white on transparent, whatever the surrounding context needs.

The sigil is **procedural**, not hand-drawn. Re-running the
generator with a different seed produces a different but
equally valid sigil. The shape is meant to be regenerated at any
boundary, not redrawn by hand. Other meaningful seeds produce
related but distinct shapes: `--seed=FUTURE` for a future-facing
branch, `--seed=JAZZ` for the musician-first identity, etc.

The sigil does **not** replace the SWR monogram (favicon.svg).
The monogram is a brand mark for the *product*. The sigil is a
character mark for the *person who built it* — same dark+cosmic
aesthetic, different role.

## How to use it

Embed the SVG directly:

```html
<img src="/press/sigil-kai.svg" alt="Kai" width="160" height="160" />
```

Or inline it and color via CSS:

```html
<svg viewBox="0 0 1000 1000" style="color: #f5a524; width: 100%; height: auto;">
  <!-- paste the contents of press/sigil-kai.svg here -->
</svg>
```

Or reference it from CSS as a background:

```css
.kai-mark {
  background: url("/press/sigil-kai.svg") center/contain no-repeat;
  color: #f5a524;
}
```

## How to regenerate

```bash
node tools/generate-sigil-kai.mjs                    # default: KAI seed
node tools/generate-sigil-kai.mjs --seed=FUTURE      # future-facing branch
node tools/generate-sigil-kai.mjs --seed=JAZZ       # musician-first identity
node tools/generate-sigil-kai.mjs --out=tmp/sigil.svg  # custom output
```

The generator is deterministic — the same seed always produces
the same shape. Run it from a deploy hook to refresh the canonical
sigil when Kai's identity is in flux.

## Where it lives in the product

- `press/sigil-kai.svg` — the canonical character mark
- `tools/generate-sigil-kai.mjs` — the generator
- `press/SIGIL-KAI.md` — this document

It does *not* replace `favicon.svg` (the SWR brand mark) or
`press/logo.svg` (the wordmark). It is the character layer.
